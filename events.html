角色事件监听

actor.on(name, callback)

在 onMounted 中注册当前存档的角色监听，返回取消监听的函数。玩家和 NPC 都支持。

js
skse.onMounted(() => {
    const player = skse.player[0];
    const off = player.on("itemAdded", e => {
        skse.console.log("获得物品", e.itemFormId.toString(16), e.count);
    });
    // 不再需要时调用 off()。重复取消返回 false。
});

最多同时注册 256 个监听；不支持的事件名、非法参数、失效角色或未进入存档时抛 TypeError。off 首次取消有效监听返回 true，重复取消/换档后取消返回 false。回调同步执行，不等待返回的 Promise。

支持的事件

所有 e 都是只读对象，包含 type 和 actor。actor 是被监听的角色包装。比较角色使用 formId，包装对象不保证相同 JS 对象身份。

事件字段与含义
itemAddeditem、itemFormId、count、otherContainerFormId；背包增加
itemRemoved同上；背包减少
activateactivator、activatorFormId；该角色被交互
deathkiller、killerFormId；原生死亡完成事件，不是濒死阶段
combatStateChangedtarget、targetFormId、state；原生战斗状态变更

物品 count 是本次事件的正数量，不代表背包最终数量。otherContainerFormId 是另一容器引用 ID；世界拾取/销毁等情况可能是 0。item 是可用于库存方法的插件物品包装；动态 FF 物品或无法解析来源插件时为 undefined，itemFormId 仍提供原始 ID。非物品记录仍可能出现在原生事件中，库存方法会拒绝不支持的类型。

activator / killer / target 只有在当前能解析为角色时才有包装，否则为 undefined；相应 FormId 仍可读取，无参与者时为 0。combat 的 state 为原生值：0 无战斗、1 战斗、2 搜索；它不会自动执行 setStatus。

监听交互

js
hero.on("activate", e => {
    if (e.activatorFormId !== player.formId) return;
    hero.setTopic({
        target: player,
        topics: [{ topicText: "需要帮忙吗？", options: [{ text: "稍后再说。" }] }],
    });
});

activate 是发生后的通知，不能阻止原生交互。setTopic 可接入同一 NPC 已经打开的原生对话菜单；另一个 NPC 的菜单仍须先关闭。同一时间只允许一个 JS 对话会话。

执行与存档寿命

原生事件线程只复制 ID/数量等值，放入有界队列；JS 回调在 SKSE 游戏任务队列并持有 V8 锁时执行。单个回调异常写日志，继续通知其他有效监听。回调可以取消自身或其他监听，新增监听不会收到注册之前入队的事件。

进入新游戏/读档时清理旧监听和旧事件，不序列化函数。每次 onMounted 必须重新注册，不应通过 Storage 保存 off 或事件对象。NPC 包装跨存档后失效，重新从 Storage 取出。

事件队列最多 1024 项；超出会丢弃并记录错误，加载过渡期间的事件也会丢弃。收集任务应在挂载、事件通知和交付前使用 getItemCount 对账，不能只累计 e.count。尚未提供 locationChanged、通用 Papyrus 事件、事件阻止、once 或事件过滤选项。

原生依据与验证状态

事件布局依据本地 SKSE 2.0.20 与 CommonLibSSE-NG ScriptEventSourceHolder、TESActivateEvent。旧 SKSE 头文件的部分事件源注释存在偏移，当前使用 SE 1.5.97 对应的实际布局。绑定已编译通过，事件到达和菜单接入仍需游戏内验证。
