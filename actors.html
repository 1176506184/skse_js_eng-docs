玩家、NPC 与物品

skse.player[0]

当前玩家的角色包装。接口操作在 onMounted 内执行。当前没有多人或玩家列表枚举；数组只提供这个入口。

skse.new({ formId, name? })

从 NPC 基础记录生成一个新角色，返回角色包装。formId 接受非零 uint32 或 0x 开头的十六进制字符串。

name 是可选的实例显示名，省略或传 undefined 时保留游戏默认名称。支持中文，1–256 个 UTF-8 字节，不能全是 ASCII 空格，不能含 NUL、换行、控制字符或 DEL；不合法时抛 TypeError，且在生成 NPC 前拒绝参数。

js
skse.onMounted(() => {
    const hero = skse.new({ formId: "0x001034E4", name: "Hero" });
    if (!hero) return;
    hero.setPosition(skse.player[0].position);
    skse.Storage.set("demo.hero", hero);
});

示例是 Skyrim.esm 的 WEFarmerMale。调用前先检查记录存在并且类型为 NPC。不存在、类型不符、VM 不可用或生成失败时，记录错误并返回 undefined。

自定义名字写入新角色引用的 ExtraTextDisplayData，基础 NPC 记录和同基础生成的其他角色保留各自名称。如果角色已经生成、但游戏未能应用名字，会记录错误并仍返回该角色，以便调用 setName 重试，避免再次生成重复 NPC。

对其他模组的 NPC，先按插件内部 ID 查询，再使用返回的运行时 ID：

js
const base = mod.getForm("0x001234"); // 替换为该模组的真实 NPC 基础 ID
if (base) skse.new({ formId: base.formId, name: "我的随从" });

actor.name / hero.setName(name)

actor.name 是只读的当前游戏显示名；引用过期或尚未进入存档时返回 undefined。不要直接赋值，已有 NPC 使用 setName：

js
skse.onMounted(() => {
    let hero = skse.Storage.get("demo.hero");
    if (!hero) {
        hero = skse.new({ formId: "0x001034E4", name: "旅人" });
        if (!hero) return;
        skse.Storage.set("demo.hero", hero);
    } else {
        hero.setName("旅人"); // 缓存角色也可以改名，不需要再生成
    }
    skse.console.log("角色名字：", hero.name);
});

setName 与 new.name 使用相同的文本校验。成功返回角色自身；引用失效或名字被原生任务/消息控制时记录错误并返回 undefined，不强行清除任务所有者。当前仅对 NPC 提供 setName；对玩家调用会抛 TypeError。

实例名称保存在游戏的引用额外数据中，不额外写入 Storage。Storage 缓存已有角色时，修改 new.name 不会重新执行创建代码，应对缓存角色调用 setName。其他模组或任务之后仍可能改变显示名；已打开的界面可能需要关闭后重开。中文是否正常显示取决于游戏字体。

实现依据本地 SKSE 2.0.20 的 referenceUtils::SetDisplayName 与 CommonLibSSE-NG 的实例改名实现。SE 1.5.97 原生入口已做静态核对并编译；名字显示、各界面刷新和保存/读档保留仍待游戏内验证。

position / setPosition(position)

js
const position = skse.player[0].position; // { x, y, z }
hero.setPosition(position);             // 成功时返回 hero

坐标必须是有限数值，绝对值不超过 100000000。接口保留角色旋转，使用该角色当前场景与世界空间；此接口不携带 Cell，因此不能直接作为跨场景传送 API。

health / attack

属性含义
actor.health当前 Health 值
actor.attack已装备武器中最大的基础物理伤害，或原生徒手伤害参考值
actor.formId只读运行时引用 ID，可用于比较事件参与者；换加载顺序时不要硬编码保存
actor.isDead只读原生死亡状态

attack 不计入锻造、附魔、Perk、难度、护甲、重击等修正，不能用于保证下一击不会致死。

actor.addItem(form, count = 1)

form 必须来自插件的 getForm 或物品事件的 item，数量是正的 int32。现在直接在 SKSE 游戏任务队列调用原生库存处理逻辑，返回前查询数量差。完整添加后返回接收角色；未完整添加或引用不可用时记录错误并返回 undefined。

js
const item = mod.getForm("0x001234");
if (item) skse.player[0].addItem(item, 1);

支持武器、护甲、弹药、书、卷轴、食材、药水、杂物、工具、钥匙、灯和灵魂石的基础记录；原生游戏仍会应用物品限制。不接受已放置的引用、FormList、Leveled List、任务或 NPC。

此 API 不复制实例附加数据，如某件已强化装备的实例状态。日志 addItem: applied 包含调用前后的数量差。参数错误或不支持的物品类型抛 TypeError。添加会使数量超过 int32 上限时拒绝调用。异常数量差时不要自动整笔重试，先查询背包。

actor.getItemCount(item)

同步查询该基础物品的背包数量，返回非负整数；引用或 VM 不可用时记录错误并返回 undefined。参数必须是本运行时生成的有效物品包装。

js
const count = player.getItemCount(flower);
if (Number.isInteger(count) && count >= 3) {
    // 可以交付；实际交付时仍会再次检查。
}

actor.removeItem(item, count = 1)

从角色背包移除物品，返回调用前后的实际减少数量。数量不足时最多移除现有数量；没有物品或引擎拒绝时返回 0。此操作不生成地上的掉落物。不指定某一件强化/附魔实例，实例选择由游戏处理。

actor.giveItem(targetActor, item, count = 1)

将物品实际转交到另一个当前存档角色的背包，返回确认转交的数量。源物品不足时返回 0，不提交部分请求。源与目标不能是同一角色。

js
const moved = player.giveItem(hero, flower, 3);
if (moved === 3) skse.console.log("交付成功");

内部使用游戏的转交逻辑，不以“删除后重新创建”模拟转交。返回值取源减少和目标增加数量的较小值；数量不符会记录错误。其他插件可能改变库存行为，因此不承诺跨插件的事务原子性。部分结果应检查双方 getItemCount，再决定补偿，不能整笔重试。

这三个修改方法的 count 均为正 int32；非法参数抛 TypeError。引用过期、角色无场景或 VM 不可用时记录错误并返回 undefined。原生游戏保留任务物品等限制，方法不绕过它们。这些新增原生绑定已编译，游戏内效果待验证。
