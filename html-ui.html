透明 HTML 界面

第一阶段开发预览，目标为 Skyrim SE 1.5.97 / SKSE 2.0.20 / Windows x64 / D3D11。DLL 和独立浏览器辅助程序已编译，6 项 UI 消息与生命周期逻辑测试通过；透明画面、输入和其他画面插件兼容性仍需游戏内验证。

安装和示例

必须使用启用了 HTML UI 的 SkyrimJS.dll，配套安装完整 UIHost。已有的普通框架 DLL 不会自动获得此功能。HTML UI 不需要额外 ESP，不暂停游戏时间。

text
Data/SKSE/Plugins/
  SkyrimJS.dll
  SkyrimJS/
    main.js
    main.html-ui-demo.js
    ui/demo/
      index.html
      panel.css
      panel.js
    UIHost/
      SkyrimJS_UIHost.exe
      libcef.dll
      chrome_elf.dll
      resources.pak
      icudtl.dat
      locales/
      ...完整运行库和许可证

不要只复制 UIHost.exe 或 libcef.dll，也不要将 Chromium DLL 放到游戏根目录。框架第一次打开页面时自动启动 UIHost，无需手动运行。

安装包根目录为 SKSE，作为 Data 内容安装；MO2 安装为独立模组并启用，Vortex 安装后部署。备份已有 main.js，再将 main.html-ui-demo.js 复制为 main.js 选择随从面板示例。源码提供有备份和哈希检查的 scripts/install-html-ui.ps1，仅在指定 -InstallExample 时切换入口。

游戏脚本

js
skse.onMounted(() => {
    const panel = skse.ui.open({
        id: "followers",
        url: "./ui/demo/index.html",
        transparent: true,
        input: "exclusive"
    });
    if (!panel) return;
    panel.on("ready", () => {
        panel.send("player:update", {
            name: skse.player[0].name,
            health: skse.player[0].health
        });
    });
    panel.on("hero:combat", () => {
        const hero = skse.Storage.get("hero");
        if (hero) hero.setStatus(skse.statusEnum.combat);
    });
    panel.on("error", message => skse.console.error(message));
    panel.on("close", event => skse.console.log("关闭原因", event.reason));
});

HTML 页面

html
<!doctype html>
<html lang="zh-CN">
<meta charset="utf-8">
<style>
    html, body { margin: 0; background: transparent; }
    section { margin: 80px; padding: 24px; background: #15202ce6; color: white; }
</style>
<section>
    <p id="health">正在读取生命值…</p>
    <button id="combat">战斗姿态</button>
    <button id="close">关闭</button>
</section>
<script>
    skse.ui.on("player:update", data => {
        document.querySelector("#health").textContent = "生命值：" + data.health;
    });
    document.querySelector("#combat").onclick = () => skse.ui.send("hero:combat");
    document.querySelector("#close").onclick = () => skse.ui.close();
</script>
</html>

页面中的 skse 仅提供 ui 消息接口，没有 player、Storage、new 等游戏 API。浏览器与游戏 V8 是不同执行环境；传递普通 JSON 数据，让游戏侧监听器操作 NPC。页面 html/body 也需要设置透明背景。

skse.ui.open(options)

参数类型 / 默认值说明
idstring，必填1–64 个 ASCII 字母、数字、下划线、点或短横线；打开期间唯一
urlstring，必填以 ./ui/ 或 ui/ 开头，指向 SkyrimJS/ui 内已有 .html 或 .htm 文件
transparentboolean，默认 true浏览器底色透明；false 使用不透明深色底色
inputexclusive 或 none，默认 exclusiveexclusive 接收输入；none 适合只显示的 HUD

返回 Panel；缺少运行库、尚未进入游戏世界、路径不存在/越界、ID 重复、超过 4 个面板、原生初始化或宿主启动失败时记录错误并返回 undefined。参数类型错误抛 TypeError。

打开是异步的，返回 Panel 只代表请求提交。请监听 ready；30 秒仍未加载完成时发 error 并关闭。skse.ui.available 是脚本初始化时检查“构建启用了 HTML UI 且 UIHost.exe/libcef.dll 存在”的结果，不保证其他文件、显卡和渲染钩子已就绪。

路径校验拒绝绝对路径、反斜杠、冒号、空字符和解析后越过 ui 根目录的路径，包括指向外部的链接。页面通过内部 https://skyrimjs.local 地址读取文件，无需 HTTP 服务。资源使用当前面板下的相对路径；不支持外部网络、外部导航、iframe 和新窗口。

Panel 方法与状态

成员返回值说明
idstring只读的配置 ID
readyboolean页面已加载且句柄未关闭
closedboolean句柄已关闭或在世界清理中作废
send(event, data = null)boolean向页面提交 JSON 消息；未 ready、已关闭、超限或发送队列不可用/已满为 false
on(event, callback)function注册监听并返回取消函数；取消函数返回是否实际移除
hide()boolean隐藏并释放输入，不销毁页面；失效/发送失败为 false
show()boolean显示并移到最上层；失效/发送失败为 false
close()boolean关闭并销毁；重复关闭为 false；手动关闭的 close 回调同步发生

最多同时打开 4 个页面，后打开或 show 的页面在上层；只有最上层可交互面板接收输入。每个面板最多 64 个事件名，每个事件最多 32 个监听器，超限抛 RangeError。事件名称以字母开头，其余为字母、数字、冒号、点、下划线或短横线，总长度不超过 64。

data 使用 JSON.stringify：循环引用、BigInt 等序列化错误向调用者抛出；函数/undefined 作为顶层数据会抛 TypeError。日期按 JSON 规则转换，不能保持对象原型或游戏对象身份。游戏侧数据限制 60 KiB UTF-8，完整协议消息限制 64 KiB；true 表示进入发送队列，不代表对方业务成功。

回调在 SKSE 游戏任务队列执行，异常写入 SkyrimJS.log，不阻止其他监听器。面板及监听器不写入存档；载入新存档/新游戏或清理存档状态时关闭，丢弃旧监听器而不回调旧世界。在 onMounted 重建页面。

内置事件与页面接口

事件callback 参数时机
readynull主页面加载完成；导航到新的本地页面会再次触发
errorstring页面加载失败、超时或渲染进程异常，随后关闭
close{ reason }script、page、escape、error、timeout、host-exit 或 renderer-error
自定义事件页面发送的 JSON 数据页面调用 skse.ui.send

页面在主 frame 的脚本运行前获得以下接口：

页面接口返回值说明
skse.ui.send(event, data = null)boolean将消息提交浏览器内部通道，不是业务确认
skse.ui.on(event, callback)function监听游戏消息，返回取消函数；名称和数量限制同 Panel
skse.ui.close()boolean请求游戏关闭当前面板

ready、error、close、request-close 为页面发送接口的保留事件，页面不能伪造。页面数据超过 60 KiB 抛 RangeError，错误参数抛 TypeError。页面回调异常进入浏览器日志。隐藏期间监听仍存在，页面计时器可能被 Chromium 节流。

输入、性能与边界

  • 游戏鼠标事件转换为虚拟光标，页面绘制光标；支持相对移动、点击和滚轮。Esc 关闭最上层可交互面板。
  • 基础键盘按下/松开和文本字符经过转发；完整中文输入法、组合输入、手柄导航、自动按键重复、拖放与系统快捷键尚未实现或验证。
  • exclusive 拦截 PlayerControls 和 MenuControls；失去游戏窗口焦点时释放拦截。关闭/切换面板后的短暂输入消隐避免 Esc 或点击泄漏到游戏。其他插件自行读取原始输入的行为不受控制。
  • 第一阶段不暂停游戏，不自动替换原生背包/地图/Scaleform 菜单。
  • 使用 CEF 30 FPS CPU 离屏 BGRA、共享内存和 D3D11 纹理上传；未做 GPU 共享纹理或脏区域上传。每个面板共享映射上限约 64 MiB，额外开销包括浏览器进程和 GPU 纹理。
  • 每边最多渲染 4096；更大游戏分辨率使用不超过此尺寸的页面再缩放，窗口尺寸变化时重新布局。
  • 浏览器原生下拉弹层、右键菜单、文件选择和开发者工具不在第一阶段支持范围，复杂控件请使用页面内元素。
  • 游戏退出通过进程作业结束整个浏览器进程树。宿主退出会关闭面板，下一次 open 可以尝试重启。
  • 开发预览禁用了 CEF sandbox，仅加载可信模组的本地页面；本地资源校验不是通用网页安全沙箱。
  • 尚未测试 ENB、ReShade、其他叠加层、独占全屏和设备丢失恢复；先用窗口/无边框模式验证。

编译与打包

修改 HTML/CSS/页面 JS，重新打开面板即可读取；修改模组 main.js 仍需重启游戏，原生代码修改需要重编译。

powershell
./scripts/prepare-html-ui.ps1 -Destination G:/Demo/skyrimjs-deps/html-ui
cmake -S . -B build -DSKYRIMJS_HTML_UI=ON `
  -DHTML_UI_DEPS_DIR=G:/Demo/skyrimjs-deps/html-ui `
  -DCEF_ROOT=G:/Demo/skyrimjs-deps/html-ui/cef_binary_150.0.22+gc1a097e+chromium-150.0.7871.256_windows64_minimal
cmake --build build --config Release --target skse_js_eng SkyrimJS_UIHost
./scripts/package-html-ui.ps1 -Zip

上述命令在已有 SKSE/V8 配置的构建目录执行；首次配置仍需基础框架的依赖参数。prepare 脚本固定版本并校验 SHA-256，支持 -Proxy '' 禁用默认本地代理。默认 SKYRIMJS_HTML_UI=OFF 可继续构建基础框架，此时 ui.available 为 false，open 记录功能未启用。

依赖固定为 CEF 150.0.22 / Chromium 150.0.7871.256 Windows x64、MinHook 1.3.4、nlohmann/json 3.12.0，放在源码仓库外。安装包携带 CEF 许可证、Chromium 第三方声明、MinHook 和 JSON 许可证；Chromium 不与现有 V8 静态库混合链接。参考 CEF 官方离屏接口。

游戏内验收与日志

1. 退出游戏，安装完整包，备份并选择示例 main.js，从 SKSE 启动、进入存档。 2. 检查 SkyrimJS/SkyrimJS.log 的 HTML UI host started 与 HTML UI ready。 3. 检查面板外能看到游戏，玩家姓名/生命值每 500 ms 更新。 4. 点击召唤旅人，再切换战斗/空闲；确认点击没有同时挥拳或打开原生菜单。 5. 输入英文/数字，测试鼠标、滚轮与 Esc；关闭后确认移动和视角恢复。 6. 再次载入存档，确认清理旧面板、打开新面板，缓存旅人不重复生成。

UIHost 诊断日志位于 %LOCALAPPDATA%/SkyrimJS/UIHost/辅助进程ID/cef.log。正常关闭时尝试清理；游戏退出终止进程树时可能保留，便于回看。示例关闭后可重新载入存档再次打开。
