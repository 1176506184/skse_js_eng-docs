任务与原生日志

任务 API 把“JS 保存的任务状态”和“原生任务日志显示”连接起来。顺序目标、进度、失败、取消、奖励回调已实现；原生日志适配已经编译，尚待游戏内验证。

最简单的任务

js
skse.onMounted(() => {
    const player = skse.player[0];
    const task = player.addTask({
        id: "myMod.testTask",
        title: "测试任务",
        description: "这是一个测试任务",
        onComplete: () => skse.console.log("任务完成"),
    });

    // 满足你自己的游戏条件时再调用：
    // task.complete();
});

addTask 只能由当前玩家调用。游戏尚未加载时拒绝操作。没有 steps 的任务保持 active，等待 complete / fail / cancel。

独立 JS 模组会自动将显式任务 ID 变为 模组ID:原ID，Tasks.get 使用本地 ID，Tasks.list 只返回本模组任务；返回的 Task.id 包含完整前缀。未提供 ID 时生成本模组的配置哈希 ID。128 字符上限包含前缀，32 个原生任务槽由所有模组共享。已有旧入口任务不自动迁移，详见 JS 模组。

多阶段任务

js
const task = player.addTask({
    id: "myMod.delivery",
    title: "一份委托",
    description: "帮助 Hero 收集物品。",
    steps: [
        { title: "与 Hero 交谈" },
        { title: "收集三瓶牛奶", total: 3 },
        { title: "返回 Hero 身边" },
    ],
    onComplete: ({ task }) => {
        skse.console.log(task.title, "已完成");
        // 在这里编写发放奖励的代码。
    },
    onFail: ({ reason }) => skse.console.log("失败：", reason),
    onCancel: () => skse.console.log("已取消"),
});

// 在对应的对话/物品逻辑回调内推进，以下语句不应全部立即执行：
// task.steps[0].complete();
// task.steps[1].addProgress(1);
// task.steps[2].complete();

目标按数组顺序进行。total 默认 1，达到后自动激活下一项；所有目标完成后自动结束任务。这个系统不自动监听获得物品、走到位置或对话，需要脚本在实际条件满足时更新进度。

配置

字段合同
id建议提供；1–128 个 ASCII 字母、数字或 _ . : -
title必填非空文本，最多 256 UTF-16 码元
description可选，默认空串，最多 4096 码元
steps可选数组，最多 32 项
steps[].title非空，最多 256 码元
steps[].total正 int32，默认 1
onComplete / onFail / onCancel可选同步函数，接收 { task, reason }

文本不能包含 NUL。任务序列化值额外限制 60 KiB，仍计入 Storage 每存档 1 MiB 的总上限。

省略 id 时按配置生成确定性 ID，同配置会复用；改变标题、说明或目标会改变自动 ID。正式模组应使用固定、带命名空间的 ID。

返回对象

属性含义
id / title / description任务定义
stateactive / completed / failed / cancelled
reason失败原因；其他情况通常为空串
currentStep当前目标下标，0 起；没有目标或已结束时为 -1
steps冻结的目标包装数组
journalnative 或 unavailable，表示最近一次日志同步结果

任务与目标包装只读；通过方法修改进度。

方法行为
task.complete()无目标时完成；有未完成目标时拒绝跳过
task.fail(reason = "")标记失败并调用 onFail
task.cancel()标记取消并调用 onCancel
task.refreshJournal()重试同步原生日志，返回布尔值
step.complete()完成当前目标
step.addProgress(amount = 1)正 int32 增量，超过 total 会钳制到 total
step.setProgress(value)非负 int32 绝对进度，超过 total 会钳制；当前未完成目标可下降

修改成功返回 true；重复完成、操作已结束任务或尚未激活的目标返回 false，不会越过下一目标。非法参数会抛出异常，宿主回调入口会记录。

setProgress 用于背包数量等可减少的进度，相同值返回 false；目标完成后不能回退或重新激活。交付任务必须再次查询实际库存，不能仅凭收集目标曾经完成就发奖励。见 完整收集任务流程。

step 的属性有 title、total、progress、state；state 为 locked / active / completed / inactive。任务失败或取消后，未完成目标为 inactive。

获取已有任务

js
skse.onMounted(() => {
    const task = skse.Tasks.get("myMod.delivery");
    const tasks = skse.Tasks.list();
});

get 缺失返回 undefined；list 返回只读数组。addTask 同 ID 返回当前存档已有包装并重新绑定回调，不重置进度。相同 ID 的步骤数、顺序、标题、total 需保持不变，变更时当前版本要求新 ID 或显式迁移策略；暂不提供重置/删除 API。

保存与奖励

每次进度变更先写入任务状态，再调用结束回调。回调抛错会记录日志，不倒退状态或自动重试奖励。不要在 onComplete 中假定奖励事务能与游戏存档原子提交。

读档恢复状态不重新触发结束回调。函数不序列化，必须在每次 onMounted 中用同一配置 addTask 绑定当前存档的函数。旧任务句柄在换档后抛出明确错误，禁止影响新存档。

已结束任务仍保留记录，占用槽位，避免 ID 复用造成奖励重复。当前每个存档最多 32 个任务，含已完成、失败、取消任务。

原生任务日志安装

运行 node scripts/build-task-carrier.cjs 生成自有的 SkyrimJS_Tasks.esp，安装到 Data 并启用。它是带 ESL 标记的 ESP，包含 32 个空 Quest 槽位，每槽 33 个目标，不复制其他模组或游戏记录。

框架只修改这个载体的任务，不接管其他 ESP 的 Quest。标题映射为原生任务名；说明作为目标区中的说明行显示；步骤显示为原生目标，数量目标附带进度。当前没有地图目标、任务别名、原生日志描述段落、语音、自动条件或完整 CK 任务脚本。

界面已打开时未必立即刷新，必要时关闭再打开任务日志。日志显示是开发中的原生适配，尚未在游戏内确认全部生命周期；存档进度核心有独立回归测试。先使用测试存档。

没有启用载体时 JS 任务继续工作，journal 为 unavailable。看到启动 pending 提示时可稍后 refreshJournal，或再次 addTask 同 ID 重试。取消任务会隐藏载体目标；原生已完成/失败任务的具体显示仍需验证。
