日志与常见问题

完全没有日志

先确认通过 SKSE 启动，DLL 位于有效的 Data/SKSE/Plugins，而不是只复制到开发仓库。检查游戏实际版本是否 1.5.97，SKSE 是否 2.0.20。

使用 MO2 时查看当前实例的 overwrite 目录，确认启用的配置实际包含 DLL 和脚本。

主菜单有日志，进入游戏没生成对象

入口执行与 onMounted 是两个阶段。先找 main.js executed、onMounted dispatch begin、具体 API 错误。生成依赖有效 NPC 基础 Form；记录引用 ID 和 NPC 基础 ID 不同。

插件 loaded 为 false

检查插件的完整文件名、依赖和当前管理器配置。游戏外文件存在不等于当前配置已启用。import 本身不会启用插件。

getForm 查不到

使用内部 ID，省略运行时高位编号。覆盖记录需按原始插件查询。轻量插件编号不能超出 1.5.97 的 12 位范围；用 ESP Explorer 确认类型、删除标记与来源。

有动画提交日志，没有可见动作

检查事件名称大小写、行为是否生成、骨骼、角色性别与场景/家具条件。提交成功只表示引擎接受请求。HKX 路径和 Idle 的 Editor ID 不等于动画事件。

对话没有出现

角色须已加载、存活且不在战斗中，target 必须为玩家，同一时间没有另一段对话。检查 setTopic 日志，原生菜单超时和 SWF 不兼容会写错误。

任务进度存在但日志不可见

检查 task.journal 和 SkyrimJS_Tasks.esp 是否在当前配置启用。原生启动 pending 时稍后 refreshJournal。说明以目标行呈现；必要时重开任务日志。当前不生成地图标记。

为什么读档后对象方法失效

角色、任务句柄绑定具体存档。读档后在 onMounted 中重新 Storage.get、Tasks.get 或 addTask。不要使用旧闭包持有的任务句柄操作新存档。

为什么奖励没有再次执行

已结束任务不会因为读档或重复 addTask 重放回调。任务进度先保存，奖励回调抛错也不自动重试；根据日志处理自己的奖励逻辑。

报告问题时提供什么

  • 游戏、SKSE 与 DLL 对应的版本/提交。
  • 最小 main.js 示例与相关日志段落。
  • 发生在主菜单、进入存档、执行动作、对话退出还是保存/读档。
  • 相关 ESP、动画框架与界面模组的版本；不要把大型游戏资源直接提交到公开文档仓库。
