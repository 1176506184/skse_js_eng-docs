跟随、等待与释放 AI 控制

目标版本 Skyrim SE 1.5.97 / SKSE 2.0.20。新增 actor.follow、wait、stopFollow 和只读 followState。使用原生临时 AI 包，不通过循环 setPosition/moveTo 模拟行走，不需要额外 ESP 或 CEF。示例面板 1.1.0 另需完整 HTML UI 运行库。

当前为开发预览：DLL 已编译，状态策略与 JS 包装逻辑有独立测试；真实寻路、过门、战斗与保存/读档表现尚待用户验证。已核对本机游戏的包类型、目标、挂载、计数和释放调用点，模拟测试不能证明游戏效果已通过。

最小流程

js
skse.onMounted(() => {
    const player = skse.player[0];
    let hero = skse.Storage.get("hero");
    if (!hero) {
        hero = skse.new({ formId: "0x001034E4", name: "旅人" });
        if (!hero) return;
        skse.Storage.set("hero", hero);
    }

    // 保留存档里已有的跟随/等待选择，不在每次挂载时覆盖。
    if (hero.followState.mode === "none") hero.follow(player);
    skse.input.bindHotkey("Ctrl+F9", () => hero.follow(player));
    skse.input.bindHotkey("Ctrl+F10", () => hero.wait());
    skse.input.bindHotkey("Ctrl+F11", () => hero.stopFollow());
});

也可用 getActor 获取其他插件已有的角色。new 生成 NPC；getActor 获取已有引用；moveTo 一次性传送；follow 持续交给原生 AI 寻路。以上快捷键仅用于示例，跟随 API 本身不依赖输入功能。

hero.follow(targetActor)

恰好传入一个当前存档的原生角色包装，目标可为玩家或另一个 NPC。源必须是 NPC，不能控制玩家 AI、跟随自身或形成已知 JS 跟随链的循环。不接受坐标、Form 包装或 JSON 对象；目标格式错误抛 TypeError。

指令接受后返回 hero；缺少角色/目标、死亡、删除、禁用、未进入存档、其他 JS 模组已有指令、已有其他临时 AI 包或总数超过 64 时记录错误并返回 undefined。源角色尚无可用 3D/AI 数据时可先接受为 pending，准备好后再提交包。相同目标的重复调用不重复安装包；显式再次调用可重试失败的提交。返回角色不等于已经开始移动或已到达。

使用游戏默认跟随行为、速度和距离；本版没有 distance/speed/teleport 选项，不使用传送追赶玩家。导航网格、门权限、目标可达性和游戏 AI 会影响移动，不能保证追过所有地图切换、快速旅行或不可达地点。

接口不修改阵营、关系等级、队友标记、招募任务或友好关系；敌对 NPC 不会因此变成友好随从，也不自动加入玩家的战斗。其他模组的招募/解雇流程仍由其自身负责。

hero.wait()

无参数。将本模组对该 NPC 的跟随指令替换为原生 DoNothing 临时包；没有跟随指令时也可直接安排等待。接受后返回 hero；多传参数抛 TypeError，运行条件失败记录错误并返回 undefined。其他 JS 模组的指令不会被覆盖。

等待期间不主动跟随玩家，战斗仍可打断等待；战斗结束后继续等待。本版没有固定等待地点的地图标记：如果战斗使角色离开原位，结束后会在战斗结束的位置等待，不承诺返回发出 wait 的坐标。它不是禁用 AI、冻结身体或永久阻止其他包。

hero.follow(player) 从等待切回跟随。setStatus(idle) 仍负责原有战斗/武器姿态处理，不切换跟随模式；结束战斗后，原来的移动指令仍保留。

hero.stopFollow()

无参数。删除本模组的 follow 或 wait 指令；若角色仍运行我们记录的临时包，通过原生入口释放，再请求正常 AI 调度重新评估。不会保存旧 AI 的裸指针，也不强行恢复过去某一帧的行为。

成功返回 hero；没有指令时重复调用也是成功的无操作。其他模组持有 JS 指令时记录错误并返回 undefined。其他插件已替换临时包时，只删除自己的记录，不结束其他插件的包。此操作不停止战斗、不解雇游戏原生随从、不删除 NPC。多传参数抛 TypeError；未进入存档或源引用失效时记录错误并返回 undefined。

建议卸载或禁用 JS 模组前先 stopFollow 再保存。框架继续安装时会尝试清理不再加载的 JS 模组留下的已知包；完全移除框架后没有代码继续清理。

hero.followState

本模组的只读快照，返回冻结对象 { mode, state, target }；旧快照不会自动更新，需要重新读取。失效角色或未进入存档时返回 undefined。target 为当前跟随目标的角色包装，等待/无指令时为 undefined，跨档应重新获取。

字段值与含义
modenone / follow / wait，本模组登记的指令
statenone：没有本模组指令
statepending：等待源角色的场景、3D 与 AI 数据
statefollowing / waiting：对应原生临时包已安装，不是到达通知
statecombat：游戏战斗 AI 接管，不重装跟随/等待包
stateblocked：其他临时包占用，或原生提交未被接受
targetfollow 的目标包装，其他模式为 undefined

每约 500 ms 在 SKSE 游戏任务队列检查已有指令，没有指令时不提交额外巡检任务。后台计时线程不直接访问 AI。死亡、删除、禁用、源或目标无法再解析时移除指令；临时卸载但引用仍存在时保留为 pending。被其他临时包占用时不抢占，释放后再尝试。原生提交连续失败最多 3 次，之后保持 blocked；检查日志并再次 follow/wait 可显式重试。

存档与多个 JS 模组

指令写入同名 SKSE co-save，包含角色、目标、模式、所属 JS 模组 ID 和已安装包 ID；加载时使用 SKSE ResolveFormId 重映射。原生临时包由游戏自身保存，框架不序列化原生指针或 JS 函数。

onMounted 前每个世界只恢复一次指令，仅恢复成功加载的 JS 入口所属记录；未加载模组会尝试释放已知包。换档先清空内存指令，避免把 A 存档的角色/包套到 B 存档。脚本仍应在挂载后从 Storage/getActor 重新获取角色并重新绑定快捷键。应保留配对的 .ess 与 .skse 文件；缺少 co-save 时无法识别旧指令的归属。

如果保存的原生包 ID 无法解析，会记录错误并避免清除身份未知的当前包；此时可能显示 blocked，需要核对存档与 AI 状态，不能因此重新生成 NPC。

全框架最多 64 条指令，每个 NPC 同时归一个 JS 模组控制。独立模组原生绑定携带自己的 ID，不能通过 stopFollow 清掉其他 JS 模组的指令；旧 main.js 使用兼容归属。其他 API 仍可能修改同一 NPC，这不是进程隔离或完整 AI 仲裁系统。

面板与游戏验证

下载随从面板 1.1.0，在 MO2/Vortex 替换同 ID 的旧 companion-ui 包，更新 DLL 并完整重启游戏。已缓存的旅人继续从同一 Storage 命名空间读取，不因更新面板重复生成。

1. 进入存档，Ctrl + 加号打开面板，召唤旅人并点击跟随；收起面板走一段路，观察行走与绕障碍。 2. 穿过可正常通行的门，观察角色是否自行跟进。 3. 点击等待，走远后观察是否留在原地，再点击跟随。 4. 触发正常战斗，观察 combat 状态及战斗结束后的原模式恢复。 5. 分别在 follow/wait 状态保存并重载，确认模式恢复、快捷键只触发一次且没有重复生成旅人。 6. 点击结束跟随，观察原有 AI 接管，并检查 SkyrimJS.log 的 movement 错误。

原生依据

布局依据本地 SKSE 2.0.20、CommonLibSSE-NG Actor 与 AIProcess。包创建使用 PACK 类型 Follow=1 / DoNothing=27，与过程编号不同；相关纠正见 CommonLibSSE-NG 更新说明。本机静态核对创建、目标句柄、0xDF 挂载槽和 run-once 清理调用点，未启动游戏验证。
