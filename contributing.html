文档维护与发布

实现什么，记录什么

每次新增或修改功能，同一提交更新对应 API 页面、功能状态和更新日志。参数、返回值、错误行为、存档寿命与游戏版本都是 API 合同的一部分。

文档不能把计划写成已实现，不能把编译通过写成游戏内验证通过。新增原生接口必须明确实际测试范围。

文档结构

text
docs/site/navigation.json    页面导航与发布地址
docs/site/content/*.md      API 与指南正文
docs/site/assets/           站点样式与搜索脚本
scripts/build-docs.cjs      静态站构建与内部链接检查
scripts/publish-docs.ps1    推送已构建的公开站点

构建器只使用 Node.js 内置能力，没有 npm 安装、开发服务器或远程脚本。Markdown 支持本文档使用的标题、段落、列表、引用、表格和代码块。

构建

powershell
node scripts/build-docs.cjs

产物位于 build/docs-site，包含公开的 ESP Explorer 页面，以及明确加入白名单的教程脚本 downloads/collection-quest.js。不会复制游戏 ESP、用户的 main.js、凭据、私有仓库历史或本地解析报告。

公开仓库 README 从 docs/site/repository-README.md 生成，赞助入口仅复制 .github/FUNDING.yml。修改爱发电链接时同步更新这两个文件、源码 README 和文档首页，然后重新发布；其他 .github 文件不复制到公开仓库。

发布

powershell
.\scripts\publish-docs.ps1

脚本构建文档，把生成后的静态文件推送到独立文档仓库 main 分支。GitHub Pages 从该分支根目录发布；首次创建 Pages 需通过仓库设置或 GitHub API 启用。

发布使用本机 Git 凭据，不把密钥或令牌写入站点、源码或 Actions Secret。文档发布仓库只存生成文件；源码更新后需运行发布脚本，同步部署。

持续检查

源码仓库 Actions 会构建站点并保留产物。对修改 src、runtime 或工具但未修改文档的提交，文档维护门禁会失败。构建检查静态链接，不启动游戏或开发服务器，不做 TypeScript 检查。

任务和完整示例逻辑可独立运行 node --test tests/tasks.test.cjs tests/collection-quest.test.cjs；Actions 也会执行。测试使用模拟存储、角色和事件，不能替代游戏里的事件投递、库存、任务日志与保存/读档验证。
