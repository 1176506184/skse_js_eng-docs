SkyrimJS 框架安装教程

安装好框架后，写 JS 不需要重新编译 DLL，修改脚本后重启游戏即可。V8 已编入 SkyrimJS.dll，普通玩家无需安装 Visual Studio、Node.js 或单独的 V8。

环境

项目当前目标
游戏Skyrim Special Edition 1.5.97，64 位 Windows
SKSE2.0.20
引擎项目固定配置的 V8 13.8.66
AE / VR / 其他运行时当前未适配

在游戏目录找到 SkyrimSE.exe，右键打开属性，在详细信息中确认版本。以运行时版本号为准，商店中的游戏名称不能证明版本兼容。

第一步：准备框架文件

文件作用是否必需
SkyrimJS.dllSKSE 插件，包含 V8 与游戏 API必需
main.js当前 JS 入口，下方提供最小示例必需
SkyrimJS_Tasks.esp原生任务日志载体使用原生任务日志时启用
SkyrimJS/UIHost 完整目录独立 Chromium 浏览器与辅助程序使用透明 HTML 界面时必需，需配套启用 UI 的 DLL

先取得作者提供的 SkyrimJS.dll。当前文档站发布文档和示例脚本，尚未提供公开的 DLL 安装包；如果只有 ESP，还没有取得框架。已有源码构建产物的位置见后面的“源码维护者”。

SkyrimJS_Tasks.esp 不包含 V8，也不会独立执行 JS。

透明 HTML 界面的独立运行库和示例入口安装见 HTML UI 教程。基础 JS 功能无需安装浏览器。

第二步：安装对应的 SKSE

到 SKSE 官方网站 取得 Special Edition 2.0.20 / game version 1.5.97，按照压缩包中的 readme 安装。已安装该版本可跳过。

  • 将 skse64_loader.exe、skse64_1_5_97.dll 和 skse64_steam_loader.dll 放在 SkyrimSE.exe 同一层。
  • 将 SKSE 包中 Data/Scripts 下的 .pex 文件安装到游戏有效的 Data/Scripts 中。
  • 启动入口使用 skse64_loader.exe，通过 MO2 管理模组时，从 MO2 中启动它。

SKSE 的运行时 DLL 放游戏根目录，SkyrimJS.dll 放 Data/SKSE/Plugins，目录不同。

第三步：安装框架

下图表示游戏运行时应看到的目录。选择下方 MO2、Vortex 或手动方式安装：

text
SkyrimSE/
  skse64_loader.exe
  Data/
    SkyrimJS_Tasks.esp
    SKSE/
      Plugins/
        SkyrimJS.dll
        SkyrimJS/
          main.js
          SkyrimJS.log           # 运行后自动生成，不必提前创建

SkyrimJS_Tasks.esp 只在使用原生任务日志时需要启用。缺失载体时 JS 任务进度仍可保存，task.journal 返回 "unavailable"，日志会提示缺失。

使用模组管理器时，把上述 Data 内容作为模组安装，并启用任务载体及所导入插件的依赖。游戏外能找到文件，不代表当前管理器配置已启用它。

MO2：创建空模组

MO2 支持空模组和归档安装，相关实现见 MO2 官方项目。只有散文件时可以这样安装，菜单名称可能随版本和语言不同：

  • 在左侧模组列表的菜单中找到“创建空模组 / Create Empty Mod”，命名为 SkyrimJS。
  • 打开该模组文件夹，放入下列文件。空模组根目录直接放 SKSE，不额外套 Data。
  • 在左侧勾选 SkyrimJS。
  • 需要原生任务日志时，在右侧 Plugins 列表勾选 SkyrimJS_Tasks.esp。
  • 在右侧 Data 视图核对 DLL 和 main.js 的最终来源，确认没有被其他模组同名文件覆盖。
  • 将可执行程序设为游戏根目录中的 skse64_loader.exe，从 MO2 启动它。
text
MO2 的 mods/
  SkyrimJS/
    SkyrimJS_Tasks.esp            # 原生任务日志可选
    SKSE/
      Plugins/
        SkyrimJS.dll
        SkyrimJS/
          main.js

DLL 不会作为 ESP 出现在右侧 Plugins 列表。左侧启用模组保证文件可见，右侧勾选 ESP 用于启用任务载体。已有正确目录结构的 Mod 压缩包，也可使用“从归档安装模组”，安装后核对相同的有效目录。

Vortex：安装并部署

先让 Vortex 管理 Skyrim Special Edition，并配置 SKSE 启动工具。使用作者提供的 Mod 压缩包；只有散文件时，可按下面结构建立临时目录，将该目录内的内容压缩成 ZIP。

text
ZIP 内直接包含：
  SkyrimJS_Tasks.esp              # 原生任务日志可选
  SKSE/
    Plugins/
      SkyrimJS.dll
      SkyrimJS/
        main.js
  • 在 Mods 页面使用“Install From File / 从文件安装”，选择 ZIP。
  • 安装后启用该模组，执行“Deploy Mods / 部署模组”。
  • 同名 main.js 冲突时选择本次要运行的脚本版本，再重新部署。
  • 需要原生任务日志时，在 Plugins 页面启用 SkyrimJS_Tasks.esp。
  • 通过配置好的 SKSE 工具启动游戏。

按钮含义见 Vortex 官方 Mods 页面说明，SKSE 工具配置见 Vortex 官方 Skyrim 指南。

手动安装：复制到游戏目录

游戏退出后，把 DLL 放进游戏 Data/SKSE/Plugins，把 main.js 放进 Data/SKSE/Plugins/SkyrimJS。需要的文件夹不存在时自行创建。需要原生任务日志时，将 SkyrimJS_Tasks.esp 放进 Data，并在实际使用的插件列表中启用。

不要把脚本放在 DLL 旁边，也不要套成 Data/Data/SKSE。最后运行 skse64_loader.exe。使用 MO2 配置的用户仍从 MO2 启动，以保证其虚拟文件和插件列表生效。

第四步：创建最小 main.js

把下面内容以 UTF-8 保存为有效的 Data/SKSE/Plugins/SkyrimJS/main.js。文件名不能是 main.js.txt：

js
skse.console.log("脚本启动，版本：", skse.runtimeVersion.toString(16));

skse.onMounted(() => {
    skse.console.log("进入存档，玩家血量：", skse.player[0].health);
});

通过 SKSE 启动游戏。主菜单阶段执行入口；继续存档或新建游戏之后才触发 onMounted，游戏对象操作放进这个回调。

该脚本只输出日志，不生成 NPC 或添加物品。

第五步：检查日志

启动到主菜单后应出现入口日志；继续存档或新游戏之后应再出现 onMounted 日志。下面列出关键行，中间可能夹有其他初始化输出：

text
SkyrimJS loaded; waiting for DataLoaded
脚本启动，版本： 1050610
main.js executed
onMounted dispatch begin
进入存档，玩家血量： ...
onMounted dispatched

日志默认写到插件脚本目录。MO2 可能重定向到该实例的 overwrite/SKSE/Plugins/SkyrimJS/SkyrimJS.log。

MO2 中也应检查文件所属模组或自定义输出模组。框架日志与 SKSE 自身日志是两个文件；SKSE 自身的日志一般位于 Windows“文档”目录下 My Games/Skyrim Special Edition/SKSE，系统重定向时路径可能不同。SkyrimJS.log 采用追加写入，查看文件末尾和修改时间来判断本次启动。

常见安装问题

现象优先检查
完全没有 SkyrimJS.log游戏 1.5.97 / SKSE 2.0.20、从 SKSE 启动、DLL 有效目录、MO2 overwrite
main.js was not found脚本应在 SkyrimJS 文件夹内，不能放在 DLL 旁边或多套一层 Data
入口空文件或过大当前需要非空 UTF-8 脚本，最大 4 MiB
主菜单有日志，没输出血量继续存档或进入新游戏，等待 onMounted
右侧 Plugins 找不到 DLL正常；DLL 由 SKSE 加载，ESP 才在 Plugins 列表中启用
任务进度存在但原生日志没有当前配置是否启用 SkyrimJS_Tasks.esp，查看 task.journal 与错误日志
修改 JS 后还是旧代码重启整个游戏；检查 MO2 文件来源或 Vortex 冲突规则及部署

版本不匹配时框架查询接口会拒绝加载，应查看 SKSE 加载日志。更多情况见 日志与常见问题。

源码维护者

普通使用者取得 DLL 后按上述步骤安装即可。维护框架源码时才需要 VS 2022 C++、Windows SDK、CMake；文档构建和 CLI 才需要 Node.js。

V8 头文件、生成配置与静态库必须来自同一份固定版本。仓库的 scripts/prepare-v8.ps1 和 scripts/build-plugin.ps1 用于准备依赖与构建 DLL；详细本机准备过程保留在源码仓库的 Windows setup 文档。

powershell
cmake --build build --config Release --target skse_js_eng
node scripts/build-task-carrier.cjs
node scripts/build-docs.cjs

DLL 位于 build/Release/SkyrimJS.dll，任务 ESP 位于 build/package/Data/SkyrimJS_Tasks.esp。覆盖 DLL 和 ESP 前先退出游戏。

重启与读档

修改内容需要的操作
JS 任务、对话或角色逻辑修改实际生效的 main.js，必要时重新部署，然后重启游戏；无需重编译 DLL
C++ 原生 API / V8 框架维护者重新构建 DLL，使用者安装对应新 DLL
原生任务日志载体安装与框架版本配套的 ESP，并在当前配置启用

当前不支持热更新入口。修改 main.js 后重启游戏进程。进入另一个存档会使原有 NPC、任务句柄和计时器失效；在新的 onMounted 中重新取得它们。

当前只加载一个有效的 main.js，没有多个 JS 模组自动发现功能。同一路径的多个脚本会互相覆盖，不会自动合并。import @skse/某插件.esp 是查询插件资源，不是执行内嵌 JS。

保留存档对应的 SKSE co-save，Storage 与 JS 任务状态通过它恢复。读档后在 onMounted 重新取得句柄和注册事件监听。新增原生能力的实际验证范围见 功能状态。
